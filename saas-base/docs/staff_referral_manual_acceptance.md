# 员工推荐佣金手工验收清单

## 前置检查

- 后端已执行数据库迁移：`py -3.10 -m alembic current` 显示当前版本为最新 head（`20260802_0001`）。
- 商家后台"更多"页能看到"员工推荐"入口（`marketingItems` 里，分销下面那一条）。

## 基本流程

1. 进入"员工推荐"页，打开"开启员工推荐"开关，选一档强度（保守/标准/激进），确认三档卡片显示的"推荐人得¥X"金额随强度变化。
2. 在"员工管理"里填姓名新建一个员工，确认列表里出现这个员工，带着一个 6 位推荐码，点"推荐码"文字能复制成功。
3. 用小程序扫码入会一个新顾客，在注册/绑定邀请码的地方填这个员工的推荐码（走 `entry/index.vue` 现有入口，跟顾客邀请顾客同一个入口）。
4. 这个新顾客首次到店消费、核销新客券后：
   - 员工推荐页的"待发放佣金"列表应该出现一条记录，显示这位员工的名字、被推荐顾客的名字、佣金金额（跟当前强度档位对得上）、状态"待发放"。
   - 这条记录**不应该**在"分销"（顾客老带新）页面重复出现。
   - 被推荐顾客自己应该正常拿到一张"到店奖励券"（不受员工推荐影响）。
5. 点"标记已发放"（表示商家已经线下把钱给了这位员工），记录状态变成"已发放"，按钮消失。
6. 关掉某个员工的启用开关后，用这个员工的推荐码再邀请一个新顾客——绑定不应该成功（走查不到有效员工推荐码的分支，视同没有推荐人）。

## 回归检查

- 顾客邀请顾客的老带新流程（"分销"页）行为不受影响：正常开关、正常三档强度、正常记录列表、正常发券。
- 员工推荐和顾客老带新两个开关互不捆绑：只开一个、关另一个，各自行为都符合预期（对应的那一侧才会有记录/发放）。
- 老数据（迁移前已存在的顾客邀请顾客关系，`inviter_type` 是 NULL）在"分销"页里仍然正常显示，没有因为新加的员工过滤条件而消失。

## 通过标准

- 员工推荐从"新建员工 → 发推荐码 → 顾客用码注册 → 首次消费核销 → 后台记一笔待发放佣金 → 手动标记已发放"能完整走通。
- 员工那一侧全程不涉及优惠券，只是一笔现金记账；顾客自己该拿的欢迎券不受影响。
- 顾客老带新的现有功能没有任何行为变化。
