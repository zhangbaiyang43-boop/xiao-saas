# 桌贴批量导出设计

日期：2026-08-27  
状态：已完成口头设计确认，等待书面审阅

## 1. 背景与目标

当前管理端“桌码管理”只能逐张查看或下载后台生成的小程序码。商家正式上线前，还需要人工把每张小程序码、桌号和固定提示文案排成可印刷桌贴，容易耗时并产生桌号与码错配。

本功能在现有桌码管理模块内增加“一键批量生成桌贴”，将当前商户选中的有效桌贴码生成以下文件：

- 每桌一张 10 × 12 cm、300 DPI 的高清 PNG；
- 一份 10 × 12 cm 单贴单页印厂版 PDF；
- 一份 A4 每页四张、带裁切线的自助打印版 PDF；
- 一份记录输出规则的说明文件；
- 将以上文件打包为一个 ZIP 下载。

本功能不修改数据库结构、不改变现有桌码或 API 字段、不重新生成小程序码、不修改小程序端，也不新增程序依赖。

## 2. 已确认范围

### 2.1 包含

- 在 `admin-h5` 的桌码管理页增加桌贴码勾选、全选和批量导出入口。
- 新增组件化的桌贴导出确认弹窗。
- 新增一个桌贴批量导出 API。
- 在 `saas-base` 新增独立桌贴渲染服务。
- 使用项目已经依赖的 Pillow 和 Python 标准库完成图片、PDF 与 ZIP 输出。
- 随服务打包一份许可允许分发的中文印刷字体资源，确保 Linux 服务器中文渲染稳定。
- 为前后端增加定向自动化测试，并生成样张进行视觉检查。

### 2.2 不包含

- 不修改桌码创建、重新生成、扫码解析或桌台会话逻辑。
- 不新增或修改数据库表、字段、索引和迁移。
- 不改变已有桌码列表接口和字段。
- 不在数据库或对象存储中长期保存桌贴导出包。
- 不提供自由拖拽设计器、多个模板、商户自定义文案或自定义颜色。
- 不自动调用微信接口重新获取更大的小程序码。
- 不代替正式印刷前的真机扫码和实物打样。

## 3. 用户操作流程

1. 商家进入现有“桌码管理”页面。
2. 桌贴码行显示复选框；其他渠道入口码不允许选择。
3. 商家可以逐项勾选，也可以点击“全选有效桌码”。
4. 页面显示当前已选数量；未选择时“批量生成桌贴”按钮禁用。
5. 点击批量生成后打开确认弹窗，展示：
   - 已选桌贴数量；
   - 成品尺寸 10 × 12 cm；
   - 300 DPI；
   - 单张 PNG、单贴 PDF、A4 四联 PDF 和说明文件；
   - 前端能够识别的异常桌码及原因。
6. 异常桌码从选择中排除，不能混入打印包。
7. 用户确认后提交导出请求。按钮进入加载状态并禁止重复提交。
8. 后端按当前登录商户重新查询并校验所有桌码。若任何项目在提交后已失效，整次请求失败，避免产生不完整或错配的打印包。
9. 后端生成文件并返回 ZIP。管理端触发浏览器下载并显示成功提示。
10. 正式批量印刷前，商家先打印一张并用两部手机真机扫描，核对页面桌号。

## 4. 输出文件结构

ZIP 文件名使用经过安全清理的商户名称和导出日期，例如：

```text
桌贴-老王川菜馆-20260827.zip
```

ZIP 内部结构：

```text
桌贴-老王川菜馆-20260827.zip
├─ PNG/
│  ├─ A01桌.png
│  ├─ A02桌.png
│  └─ ...
├─ PDF/
│  ├─ 单贴印厂版.pdf
│  └─ A4四联打印版.pdf
└─ 导出说明.txt
```

桌号文件名必须清理路径字符，并在清理后发生重名时追加稳定序号，防止文件覆盖。ZIP 条目必须阻止 `../`、绝对路径和控制字符。

`导出说明.txt` 包含成品尺寸、分辨率、导出时间、桌贴数量、打印方式和“使用实际大小/100%，不要适应页面”的提示。

## 5. 印刷版式

### 5.1 单张画布

- 成品尺寸：100 × 120 mm。
- 输出分辨率：300 DPI。
- 像素尺寸：1181 × 1417 px。
- 色彩模式：RGB。
- 背景：纯白。
- 外边框：浅灰细线、圆角，距成品边约 3 mm，留出裁切安全区。

### 5.2 内容层级

从上到下保持固定结构：

1. 左上主标题“扫码点餐”。
2. 右上绿色桌号牌，显示动态桌号和固定“桌”字。
3. 副标题“微信扫码 · 本桌下单”。
4. 中间完整小程序码，约 62 mm，保留原始正方形和静区。
5. 底部提示“加菜也扫这里”。

小程序码只能等比缩放并完整放入指定区域，不允许裁剪、拉伸、旋转、滤镜、描边或覆盖。源图解码后合成到无损 PNG；不能把管理端缩略图截图作为输入。

桌号优先使用标准字号。桌号较长时自动缩小字号但不换行；缩至允许的最小字号仍放不下时，导出失败并明确指出对应桌号。桌号最大长度继续服从已有字段约束，不修改数据结构。

### 5.3 PDF

单贴印厂版 PDF：

- 页面物理尺寸精确为 100 × 120 mm。
- 每张桌贴单独一页。
- 页面顺序与请求中的桌码顺序一致。

A4 四联打印版 PDF：

- 页面尺寸为 210 × 297 mm。
- 每页两列两行，共四张 100 × 120 mm 桌贴。
- 四张桌贴整体水平、垂直居中。
- 桌贴之间和四角提供细裁切线，裁切线不得进入成品区域。
- 最后一页不足四张时保持固定槽位顺序，其余槽位留白。

## 6. 管理端设计

### 6.1 页面修改

现有 `EntranceCodeList.vue` 保留创建、查看、下载、重新生成、停用和筛选逻辑，只增加批量选择工具：

- 桌贴码行复选框；
- 已选数量；
- “全选有效桌码”；
- “批量生成桌贴”主按钮；
- 导出确认弹窗。

“有效桌码”的前端条件为：渠道为桌贴码、状态正常、桌号非空、生成状态成功且有图片地址。前端过滤只用于即时反馈，不能替代后端校验。

### 6.2 组件边界

新增 `TableStickerExportDialog.vue`，只负责：

- 展示选中数量和输出规格；
- 展示前端已识别的异常项；
- 显示生成中状态；
- 发出确认和关闭事件。

桌码选择状态和 API 调用仍由 `EntranceCodeList.vue` 管理，避免弹窗持有列表业务状态。

### 6.3 下载请求

在现有 API 模块增加一个独立导出方法。请求体只包含：

```json
{
  "entranceCodeIds": ["1001", "1002"]
}
```

单次最多 100 张。导出请求使用独立的较长超时和 Blob 响应，不改变 Axios 实例的全局 10 秒超时。下载完成或失败后必须释放浏览器对象 URL，并恢复按钮状态。

## 7. 后端设计

### 7.1 API

新增：

```text
POST /api/v1/entrance-codes/table-stickers/export
```

请求使用新模型接收 `entranceCodeIds`。字段使用 camelCase，对内映射到服务参数，不修改现有请求模型。

成功响应为 `application/zip` 文件流，并通过 `Content-Disposition` 提供安全文件名。文件下载是统一 JSON 成功结构的唯一例外；校验失败、权限失败和生成失败继续使用项目现有标准 JSON 错误结构。

### 7.2 校验顺序

后端根据当前租户上下文查询请求中的桌码，并逐项验证：

1. 请求数量在 1–100 之间，且没有重复值。
2. 每个桌码都属于当前登录商户。
3. 每个桌码都是桌贴码。
4. 状态正常。
5. 桌号非空。
6. 生成状态成功且存在图片地址。
7. 图片路径来自现有桌码图片存储位置。
8. 图片文件存在、大小受限、魔数合法且能由 Pillow 完整解码。
9. 桌号能在桌号牌允许范围内排版。

不能返回或泄露其他租户桌码是否存在。缺失、越权和无效输入使用统一失败语义。

### 7.3 渲染服务

新增边界清晰的桌贴导出服务，负责：

- 加载并校验印刷字体；
- 将单个桌码渲染为固定规格 PNG；
- 生成单贴单页 PDF；
- 生成 A4 四联 PDF；
- 写入说明文件；
- 打包 ZIP；
- 管理临时目录和清理。

服务使用 Pillow 和 Python 标准库。页面逐张渲染到临时目录，PDF 按页读取并及时释放图像对象，避免一次保留全部高清画布。实现不得在进程级共享可变图像对象。

字体资源必须采用允许随软件分发的开源字体，并保留对应许可证文件。服务启动或导出时若字体不可读取，应明确失败，不能降级到无法显示中文的默认字体。

### 7.4 临时文件

- 每次请求创建独立随机临时目录。
- 临时目录只包含本次请求产生的文件。
- ZIP 通过文件流返回。
- 响应完成、客户端断开或生成异常时都执行清理。
- 不在数据库、静态目录或对象存储中保留导出包。

## 8. 错误处理

管理端错误文案按用户可操作方式表达：

- 未选择：请选择至少一个有效桌码。
- 桌码失效：桌码状态已变化，请刷新后重新选择。
- 图片缺失：该桌码还没有可用图片，请先重新生成。
- 桌号过长：桌号无法放入桌牌，请缩短桌号后重试。
- 数量超限：单次最多导出 100 张。
- 生成超时：生成时间较长，请稍后重试；不得自动重复提交。
- 服务器生成失败：桌贴生成失败，原桌码不受影响。

后端日志记录租户、请求数量、成功或失败、耗时和稳定错误码，但不记录完整 ZIP、图片二进制或敏感认证信息。

## 9. 测试与验收

### 9.1 后端自动化测试

- 请求为空、重复、超过 100 张。
- 其他租户桌码不可导出且不泄露存在性。
- 非桌贴码、停用桌码、空桌号、失败状态和缺图。
- 损坏图片、伪造扩展名、超限图片和不允许的路径。
- PNG 精确为 1181 × 1417 px。
- 小程序码区域保持正方形、未裁剪并位于规定区域。
- 中文、数字、字母桌号可渲染。
- 超长桌号按规则缩放或明确失败。
- 单贴 PDF 页面为 100 × 120 mm，页数等于桌数。
- A4 PDF 页面为 A4，页数等于 `ceil(桌数 / 4)`。
- ZIP 文件结构、中文文件名、安全路径和重名处理。
- 成功、校验失败、渲染失败和文件流异常后的临时目录清理。

### 9.2 管理端自动化测试

- 只有桌贴码可以选择。
- 全选只选择有效桌码。
- 未选择时导出按钮禁用。
- 异常项在确认前列出并排除。
- 请求字段为 `entranceCodeIds`，不修改现有接口字段。
- 导出请求使用 Blob 和独立超时。
- 重复点击被阻止。
- 成功下载和失败后都恢复状态并释放对象 URL。

### 9.3 视觉与实物验收

1. 使用包含短桌号、字母桌号和较长桌号的固定样例生成 ZIP。
2. 渲染并检查单张 PNG、单贴 PDF 和 A4 四联 PDF。
3. 确认边框、字号、桌号牌、二维码静区、裁切线和最后一页空槽位。
4. 先以 100% 比例打印一张 10 × 12 cm 样张。
5. 用两部手机分别在常见桌面光照下扫码。
6. 核对进入商户、桌号和点餐页均正确后，才允许批量印刷。

自动化测试不能替代第 4–6 步的实物扫码验收。

- 新增桌贴导出服务文件

- 对应的前后端定向测试

实施时如果发现必须修改数据库、现有 API 字段、桌码生成逻辑、全局请求配置或新增依赖，应停止实施并重新请求确认，不能自行扩大范围。

## 11. 完成标准

满足以下全部条件才算完成：

- 商家能在桌码管理页勾选并批量下载 ZIP。
- ZIP 同时包含逐桌 PNG、单贴 PDF、A4 四联 PDF 和说明文件。
- 所有输出尺寸、页数和文件结构通过自动化检查。
- 其他租户桌码无法被读取或导出。
- 没有数据库、现有 API 字段、小程序端或无关模块变更。
- 前后端定向测试、管理端构建和后端相关回归通过。
- 样张完成视觉检查。
- 正式印刷前的单张实物扫码验收被明确保留为人工发布门槛。
