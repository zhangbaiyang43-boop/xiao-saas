本桌订单，一套样式两种场景

把「桌贴结账（统一结账）」和「先付后吃」两种下单方式收进同一个面板：补齐前者缺失的进度、订单号、支付状态，收敛后者过载的四宫格与嵌套提示。下面是 A / B 两版方案，切换场景即可对照。

两版怎么选

两版信息量完全一致，差别只在结构密度。桌台多轮加菜的店更需要 A 的分单可读性；单次点单为主、追求「看一眼就收起」的店更适合 B。

方案 A · 分段式

  • 整幅状态条：颜色随状态变（待接单=琥珀 / 制作中=绿 / 已完成=绿），标题加一句人话提示。
  • 四步进度轴：已下单 → 接单 → 上齐 → 结账；先付后吃场景首节点换成「已支付」。
  • 按下单批次分组：每一「单」带时间和自己的状态标签，加菜多轮时不会糊成一片。
  • 适合：包间 / 大桌 / 反复加菜的正餐店。

方案 B · 聚合式（已按评审调整）

  • 一张摘要卡：状态胶囊 + 提示 + 身份信息同框，卡内平铺菜品，卡底压合计。
  • 进度压缩：一排小圆点铺满整行，两端固定文字框住「从哪到哪」，下面右对齐一句 已等待 X 分钟 给等餐的人时间感。
  • 菜品行 32px 缩略图：纯文字行认菜成本高，尤其大桌多批次；取不到图落占位图。
  • 批次弱化：单批次不出状态标签（顶部胶囊已经说了）；多批次才用行内小标签（1单）。
  • 加菜提示只在第一单出现：加过一次后顾客已经知道会合并，常驻是噪音。
  • 适合：快餐 / 小吃 / 单次点单为主、希望面板尽快收起的店。
